## Summary

The goal of this feature is to implement the foundational core of the Onboardly client onboarding system. The technical approach leverages a Go backend utilizing `go-chi/chi` for API routing and a Vue.js 3 frontend using Vite and Pinia. A PostgreSQL database guarantees referential integrity between clients, projects, and meetings, while a webhook receiver processes real-time client ingestion from Google Sheets (Salesforce exports).

## Technical Context

**Language/Version**: Go 1.22+ (Backend) and HTML5/Javascript with Vue.js 3 + TypeScript (Frontend)

**Primary Dependencies**: `go-chi/chi` v5, `jackc/pgx` v5, `golang-jwt/jwt` v5, `bcrypt` for Go; `pinia`, `vue-router`, and `axios` for Vue 3.

**Storage**: PostgreSQL

**Testing**: `go test` with `stretchr/testify` (Backend); `vitest` with Vue Test Utils (Frontend)

**Target Platform**: Docker / Linux Server (Backend); Modern web browsers (Frontend)

**Project Type**: Web application (frontend + backend)

**Performance Goals**: API response time under 500ms for logins, webhook sync under 1.5s, dashboard rendering under 2s.

**Constraints**: Strict referential integrity constraints enforced by the DB layer; Dates stored and processed only in ISO 8601/RFC3339 format.

**Scale/Scope**: Core system MVP supporting onboarding tracking for up to 10,000 users.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Gate 1: Access Control & Cryptography**: Verified. User credentials hashed using bcrypt, and sessions verified using secure, cryptographically signed JWT.
- **Gate 2: Database Referential Integrity**: Verified. PostgreSQL foreign key constraints strictly block any orphan meetings.
- **Gate 3: Universal Chronology**: Verified. All datetime values must use the ISO 8601 format.
- **Gate 4: Integration Security**: Verified. Google Sheets webhook endpoints require the `X-Webhook-Token` shared secret header.
