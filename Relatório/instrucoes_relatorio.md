Instruções

Aplicar a ferramenta SonarQube em um projeto de software real para analisar indicadores de qualidade, identificar problemas no código-fonte e propor ações de melhoria baseadas nos resultados obtidos.

Descrição da Atividade
Selecionar um projeto desenvolvido na disciplina ou reutilizar um projeto existente de outra disciplina (Node.js, Java, C#, Flutter, Web, Mobile, etc.).

Após a escolha do projeto, configurar e executar uma análise utilizando o SonarQube Community Edition, gerando métricas e relatórios de qualidade do código.

O objetivo não é necessariamente corrigir todos os problemas encontrados, mas compreender os indicadores apresentados pela ferramenta e propor ações de melhoria.

Entregável
Entregar um relatório em formato PDF contendo os itens descritos abaixo.

1. Identificação do Projeto
Nome do projeto;
Objetivo do sistema/aplicação;
Tecnologias utilizadas.
2. Configuração da Análise
Descrever brevemente:

Versão do SonarQube utilizada;
Linguagem de programação analisada;
Forma de execução da análise;
Data da análise.
3. Resultados Obtidos
Inserir capturas de tela (prints) do SonarQube contendo, no mínimo:

Visão Geral (Overview)
Quality Gate;
Reliability;
Security;
Maintainability;
Coverage;
Duplications.
Métricas
Apresentar os valores encontrados para:

Linhas de Código (Lines of Code);
Cobertura de Testes (Coverage);
Complexidade Ciclomática (Complexity);
Complexidade Cognitiva (Cognitive Complexity);
Duplicação de Código (Duplications);
Bugs;
Vulnerabilidades;
Security Hotspots;
Code Smells;
Dívida Técnica (Technical Debt);
Índice de Manutenibilidade (Maintainability Rating).
4. Análise dos Problemas Encontrados
Selecionar pelo menos:

3 Code Smells;
1 problema relacionado à Segurança (Vulnerability ou Security Hotspot);
1 problema relacionado à Complexidade ou Duplicação.
Para cada item apresentar:

Descrição do problema;
Arquivo e trecho do código afetado;
Explicação do motivo pelo qual o SonarQube considera o item um problema;
Possíveis impactos na manutenção, segurança ou evolução do sistema.
5. Plano de Correção
Para cada problema analisado, descrever:

Como pretende corrigi-lo;
Qual melhoria será obtida após a correção;
Grau de prioridade (Alta, Média ou Baixa).
Não é obrigatório implementar as correções, apenas apresentar uma proposta técnica consistente.

6. Conclusão
Apresentar uma reflexão sobre:

A utilidade do SonarQube no processo de desenvolvimento;
Quais métricas foram consideradas mais relevantes;
Principais problemas encontrados no projeto;
